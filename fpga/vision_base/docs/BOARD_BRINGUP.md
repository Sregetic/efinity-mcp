# 硬件到位后的接入步骤

预计日期2026-09-09；这是执行清单，不是定时任务。先基于实物与示例建立工作点，再接新核心。

## 1. 识别并冻结实际板卡

需要开发板正反面、FPGA丝印、PCB版本、相机模组及转接板、屏幕转接板和当前接线照片。商家所称Ti60F225I3只确定芯片基线，不足以选择某厂商的整个peri.xml。

已知原V4包与VF奥唯思包的板级资料不同。优先选择与实物一致的板级接口，其余只取逻辑参考。SC431HAI相机的lane数、FPC方向、供电、参考时钟及复位极性按实际模组核对。

## 2. 保留供应商直通基线

候选为原包SC431HAI→HDMI V6，不默认将其全部直接升级成主工程。核对活动CSI为rtl目录下5.15实现，而不是仅查看ip/settings的5.16；补齐未填写的CLK_25M约束，并检查生成后的时钟关系。先保存原始基线，再建立一个明确的板卡工程，不复制多个工作树盲目比较编译。

通过当前工具验证：完整源码依赖、时钟/接口生成、综合、P&R、约束覆盖、下载器识别和DDR校准。依次显示色条、相机测试图、真实彩色图，记录相机帧率与屏幕刷新率，不混为一项。

## 3. 接入新核心

当前核心接受RGB565帧。相机解包/去Bayer后形成16-bit格式，采集适配器在SOF向frame_pool申请bank，仅在获得bank后写入该帧；帧错误或写入失败不发布。相机继续发数据且无可写bank时丢弃整帧并计数，禁止写入读者持有的bank。

帧发布以写事务完成为界：仅发完最后W数据还不够，应收齐对应B响应并检查错误，再发cap_done_ok。申请时锁存capture配置ID；处理job的config_id可以与capture配置不同，例如对冻结帧修改ROI。源frame_id持续保持对应关系。

frame_pool只管理bank编号；上层地址表将bank映射为DDR起始地址和跨度。显示/分析任务先获取租约，将相应base/stride/尺寸传给roi_axi_scaler，直到done才按需要释放。冻结显示时持续持有，重新渲染同一帧也保持源数据不变。display与analysis是两个不同持有者；本版 frame_render_engine 已实现源帧申请、冻结/实时切换和结果写回调度；像素采集与显示扫描适配器仍需接入。

AXI行读取器用128-bit读总线，ARID固定0。合入SoC或第二读者时应在单一仲裁点分配请求与ID，并保证显示最低服务带宽；不直接并接AXI主口。现有DDR私有控制/PHY保持厂商实现，不将其加密内部逻辑视为已经审计。

缩放输出有行读取停顿。首轮写入结果帧，再由显示扫描读出，或在经过时延预算后使用显示FIFO。禁止直接把任意背压pixel_valid当作连续HDMI DE。结果帧只有EOF、写响应和任务error均合格才交给显示。

## 4. 首轮可检查的上板结果

1. 原始相机画面稳定，颜色与方向正确。
2. 输出保持固定模式，中心区域2x放大并能移动ROI。
3. 非整数倍率和缩小正常，无跨行跳变。
4. 冻结显示后移动相机，冻结内容不变；恢复后显示新帧。
5. 同时发起analysis取帧，显示和采集仍按协议运行。
6. 保存资源、时序、DDR错误/溢出/丢帧、渲染周期数；在此之前不填写已达成的FPS。

## 5. 接LCD

HDMI基线通过后，接入单路DSI。V3.5例程中有两套DSI实例，按单屏实物裁减。用户屏幕手册存在第5页外形图与第6页接口表电源脚标注差异，先确认匹配的转接板图纸，再选择显示初始化。面板为无触摸，按键提供基本模式/阈值操作。

## 6. 已准备的诊断制品与状态

- `artifacts/pattern/ti60f225_oob.bit`：固定 1080p60 八色条、白色边框和移动方块；显示复位不等待相机配置完成，用于先核对 HDMI 时钟、连接和 RGB 通道。
- `artifacts/camera/ti60f225_oob.bit`：相机/DDR/去马赛克直通。相机版保留供应商颜色路径，实际颜色用红绿蓝色卡验证。
- `artifacts/timing_probe/`：新 RGB565 引擎的物理时序检查版本，使用片内合成 AXI 服务；不是物理 DDR 运行测试。

LED 逻辑信号定义（亮灭极性按实际 PCB）：`led[0]` 为 DDR 校准完成后的 core 时钟心跳；`led[1]` 为输出帧计数 bit5；`led[2]` 为三个基础 PLL 锁定组合状态；`led[3]` 为接收帧计数 bit5。约每 32 帧翻转一次的信号只能判断帧活动，不是精确 FPS 计量。timing_probe 中 LED2/3 分别替换为引擎 active 和写数据校验活动。

上板证据填写 `results/hardware_acceptance.template.json` 的副本，保留板卡身份、所用 bit 文件 SHA256、示波器/ILA计数以及异常项；模板中的 null 表示尚未测量。
原例程的 w_confdone 固定为1，并非相机 I2C 应答或配置成功信号。本次不将它当成相机就绪证据；相机状态仍通过实际接收帧、图像和必要的 I2C/ILA 观测判断。

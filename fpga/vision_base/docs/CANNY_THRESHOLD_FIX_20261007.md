# Canny弱轮廓漏检：阈值同帧复核

2026-10-07。用户反馈轮廓变少/断线。当前Canny单独从128调为96，Sobel仍96、中值开启、原图模式M0/实时F0/ROIoff恢复；位流、AI固件、Flash均保持。

## 根因与修复

读取当前真实灰度、Sobel和Canny条带发现：三条竖缝在灰度/Sobel清楚，Canny128下大量消失。历史2026-10-06正常九图的Canny头为96；本次当前独立Canny为128。较高强阈值使低对比度线条缺少强种子，整段弱轮廓在滞后连接/组件剪除时被筛掉。

随后在同一冻结原帧250350、相同中值/tone/位置/384行范围，仅改Canny阈值。下面是实际FPGA输出，不是主机重画的边缘：

|Canny设置值|白像素|连通组件|三条竖缝覆盖行数|面积≤12的小组件|
|---|---:|---:|---|---:|
|128|768|2|0/384/0|0|
|96|2304|6|384/384/384|0|
|64|2304|6|384/384/384|0|
|48|2304|6|384/384/384|0|

每条缝有两个边缘，所以三条缝对应六个连续组件。96、64、48的掩码逐像素相等；128掩码是96的子集。选择保住轮廓的最高测试值96，没有为追求白像素继续降低到48。测试范围为1920×384、y300..683，不将这个条带的零小组件推广为所有场景全图零噪声。

## 实时复核

不冻结原帧、不hold Canny平面，采样y480上三条缝的三个窄带。14.75秒60次采样，三条线各0次消失，每带至少2个边缘像素；源帧278659→279101，Canny完成24730→25173，约30.0339次/秒。检查脚本会拒绝hold状态或没有源帧/Canny完成数进展的情况，不用固定图冒充实时。

参数修改和回读期间capture discard/scan bad新增均0，原scan bad152保留。Canny仍480×270分析、1080p单像素邻接轮廓，MIN_COMPONENT32和噪声自适应下限保持；本次修复不需要削减算法或更换位流。最新数据见`results/canny_regression_20261007/ab_summary.json`、`summary.json`、`live_qualified.json`、`final.json`。

本次只修当前阈值配置，不改位流reset默认值。后续重烧时应按current_state.json保存的Sobel/Canny独立值恢复，避免再次覆盖为128。灯光和物体改变时继续使用实体键或面板调节，两个阈值的职责保持独立。

## 可复测入口

`check_canny_live.py`只读当前M5显示行，不切换模式、不冻结；运行前切M5，结束恢复原模式。示例（Efinity Python环境）：

```powershell
python scripts/check_canny_live.py --url ftdi://0x0403:0x6011:4:9/2 --row 480 --bands 256 305 850 899 1454 1503 --seconds 15 --output results/canny_live.json
```

窄带对应本次场景竖缝，换场景时按实际位置选带。这是抽样检查，不宣称检查了每帧每个像素。

# Ti60F225I3 视频项目：识别与 TinyML 接入技术说明

版本：V0.1，2026-09-18。本文保留原接入设计。2026-09-19更新：A6单目标几何识别已移植、仿真、编译和烧录，实物验收待完成，当前证据见SHAPE_RECOGNITION_20260919.md。TinyML/RISC-V仍属后续扩展。

## 1. 目标和术语

当前功能基线为 SC431HAI → MIPI CSI → RAW处理/DDR帧缓存 → 去马赛克/颜色及亮度处理 → HDMI 1920×1080@60Hz。已有灰度、中值、Sobel、Canny、冻结、六帧回放和边缘叠加。显示刷新率、采集新帧率、识别推理率分别统计。

赛题高阶挑战6要求圆形、矩形等简易目标识别，允许用轮廓和几何特征；不强制神经网络。本文将传统形状识别和可选神经网络推理分为两条路线。TinyML是扩展方向，不应替代或扩大原赛题要求。

## 3. 当前工程证据与限制

2026-09-18 HDMI构建：XLR 54870/60800，RAM216/256，DSP67/160；名义剩余分别5930、40、93。最终WNS+0.339ns、WHS+0.026ns。依据[最新构建状态](F:/Project/fpga/vision_base/results/board.compile.status.json)和[路由报告](F:/Project/fpga/vision_base/board/ti60f225_v4/outflow/ti60f225_oob.route.rpt.xml)。这是该次构建快照，后续改动需重新综合。

剩余DSP较多不等于可直接加入完整AI系统：控制、数据搬运、指令缓存、张量缓存及互连会占用逻辑/RAM，还会改变布线。当前未验证有可用的RISC-V/TinyML运行环境。

[frame_render_engine说明](F:/Project/fpga/vision_base/docs/frame_engine.md)定义了一套RGB565 ROI/读写引擎，但它仍是独立模块验证边界：当前实机RAW8 DDR路径并未完整接入这个引擎。不得直接把现有RAW8缓冲区地址交给RGB565读者。该文档中的默认24MiB地址布局也不是已核实的板级空闲内存分配。

## 4. 路线A：几何形状识别

推荐先满足原赛题最小闭环：圆形/矩形/未知三类，在稳定光照、明确前景目标下工作。

处理流程：已完成灰度或边缘帧 → 可选二值清理 → 连通域/轮廓 → 面积、边界框、周长、顶点或角点 → 判别 → 结果帧提交 → HDMI文字/框叠加。

输入可先用480×270分析图，显示保持1080p。识别与原图使用frame_id关联；空间缩小比例、ROI偏移和流水线边界裁剪必须一起保存。小目标或细线可能被缩小丢失，验收时需记录最小目标尺寸。

特征候选：
- 边界框宽高比、面积、中心、边界接触标志；
- 圆度4πA/P²；注意A需是填充区域面积，不是Canny边缘像素数量，P需与所用轮廓估计方式一致；
- 矩形候选的多边形顶点数、邻边夹角、闭合程度；倾斜矩形不应只用轴对齐框填充率判断；
- 开口轮廓、遮挡、过小区域和复杂噪声输出unknown，不强行分类。

乘除开方等复杂几何计算可对少量候选在帧级进行，而不是在每像素通路重复实例化。纯RTL、软核或主机验证都可作为阶段实现，但最终平台选择必须与提交要求一致。选择CPU实现需要计入CPU自身资源。

## 5. 路线B：TinyML神经网络推理

源资料路线为Sapphire RISC-V软核 + TFLite/TFLite Micro相关库 + 自定义指令或硬件加速器。CPU承担任务调度、模型调用、后处理；FPGA承担确定收益的预处理和算子。当前尚未集成。

原手册示例使用Raspberry Pi V2、HyperRAM和Mini-DSI，当前使用SC431HAI、DDR和HDMI。移植必须逐项替换相机驱动、DMA/外存控制、地址空间、缓存一致性、像素格式和显示后处理。禁止直接沿用示例bitstream、引脚表或DDR/HyperRAM地址。

任务选择：整幅分类只输出类别，不能自然提供多个目标位置；检测需要位置输出和检测后处理。资料列出96×96×3行人检测示例、96×96×1人物存在检测、32×32×3分类示例；这些仅作为候选规模，不是本项目已经选定的模型。

流程：定义任务和类别 → 数据集独立划分 → PC浮点基线 → INT8量化 → PC量化推理 → 核对算子集合 → 板上软件基线 → 分析耗时 → 对热点加入加速 → 整机验收。先证明模型有效，再评价硬件加速。

## 6. 统一输入与量化契约（设计提案）

每份识别输入描述符至少包含：frame_id、config_id、buffer_base、width、height、stride_bytes、pixel_format、ROI(x,y,w,h)、resize方法、颜色顺序、tensor layout、量化scale与zero_point。它们必须由生产者发布后保持稳定至消费完成。

训练/部署一致性必须覆盖RGB/BGR、灰度权重、resize插值、拉伸或letterbox、归一化顺序、INT8/UINT8符号、裁剪和舍入。不要把图像字节0..255直接转成int8后就当作已完成量化。

量化关系：q=clamp(round(real/scale)+zero_point)，real=scale×(q-zero_point)。real的定义必须匹配训练预处理；权重可能按通道量化。推理前读取实际模型张量信息，不猜固定偏移128。

将模型文件hash、类别表、量化信息、预处理版本、算子及版本列表、arena实测峰值、PC测试输出一并归档。摄像头暗场、曝光和白平衡变化需体现在数据/验收中；当前tone临时对照设置也应记录，不能训练和部署两套预处理。

## 7. 存储和带宽预算

以下只计算输入张量净载荷，不包含权重、激活、对齐和DMA开销：

|输入|INT8字节数|KiB|
|---|---:|---:|
|96×96灰度|9216|9|
|96×96RGB|27648|27|
|160×160RGB|76800|75|
|224×224RGB|150528|147|
|320×320RGB|307200|300|

双缓冲输入占用加倍。模型Flash文件大小不等于运行RAM需求；还需中间激活、tensor arena、scratch、栈、CPU缓存和DMA队列。完整1080p RGB888约5.93MiB，RGB565约3.96MiB，连续存储应优先使用经核实的DDR区域。

仅以1080p RGB888单次全帧读取、30fps计，净载荷约186.624MB/s；若抓取流中分支生成96×96RGB、30fps，输出张量净载荷约0.82944MB/s。后者不代表整个系统带宽只有这个值；前级采集、显示和算法仍占用总线。

优先复用预处理结果，片上保留必要行缓存/小tile，大帧和适合外存的张量放DDR。DDR仲裁需给显示设延迟保障；AI过载可丢弃过时待处理帧，仍须保护正在读取的源帧。不要让AI反压直接停止HDMI扫描。

## 8. 识别结果与显示契约（设计提案）

结果记录：frame_id、config_id、model_id、class_id、score、bbox、valid、overflow、处理周期数。结果生成后原子发布，在显示帧边界切换。

ROI坐标还原：x_src=x_roi+x_model×roi_width/model_width，y同理；letterbox模式需先扣padding再除scale。量化舍入、边界限幅、分析图裁剪必须一致。

选择两种明确策略之一：严格结果帧与源帧配对（付出缓存和等待延迟）；或在实时画面显示最新结果并报告其年龄（移动物体可能错位）。当前Canny叠加已有结果滞后风险，接入识别时不能忽略这个问题。

## 9. 自定义指令与加速器边界

源资料CI使用cmd/rsp与valid/ready握手，rs1/rs2提供操作数，func ID区分操作。只有valid&&ready才转移一次事务；背压期间保持结果和元数据。复位清除未完成事务，避免重复提交。

从逐算子profiling决定加速对象；不要假设卷积、矩阵乘、加法都值得同时做硬件。定点实现检查输入零点、偏置、累加范围、重定标、舍入和饱和。标称INT32累加不代表任意核尺寸都没有溢出，需按值域分析。

复杂访存任务可用DMA/描述符接口，逐次小运算可用CI。两者寄存器地址、指令编码和CPU缓存处理尚待实际SoC生成后确定，本文不虚构MMIO地址。

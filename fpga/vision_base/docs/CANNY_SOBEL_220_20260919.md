# Canny / four-stage Sobel optimization — 2026-09-19

## Scope

Ti60F225 I3, SC431HAI camera and HDMI primary output. Preserve camera mode,
ISP/color/exposure settings, HDMI 1920x1080 60 Hz, and 480x270 Canny analysis.
LCD and recognition are outside this change. Source changes are limited to
Sobel pipeline, aligned frontend/display threshold output, and Canny hysteresis
memory scheduling. No new full-frame RAM.

## Four-stage Sobel

1. Register left/right/top/bottom weighted 3x3 sums (10-bit unsigned).
2. Register signed Gx/Gy (11-bit, -1020..1020).
3. Register |Gx|+|Gy| and the 106/256 direction-comparison terms.
4. Register magnitude, quantized direction, threshold decision and metadata.

Initiation interval is one pixel/clock. Metadata and changing thresholds follow
exactly the same four stages. Existing direction boundaries and L1 magnitude
are bit-exact; frontend RGB and sync are delayed with their pixel metadata.
This adds latency, not a per-pixel throughput stall.

## Canny throughput changes

- Prefetch the next center during ADVANCE, removing the per-pixel CUR_READ bubble.
- During NCHECK, consume one BRAM result while reading the next neighbor.
- Keep exact 8-connected propagation until convergence, with no fixed iteration cap.
- Keep two output planes; only publish completed results at a frame boundary.
- Optional REUSE_CAPTURE_MAP=1 overwrites each mutable classification and edge
  pixel on every capture, including zero values. Both output planes initialize
  once. Publication immediately arms capture instead of clearing a full map and
  waiting for an additional frame boundary.
- The reuse contract requires complete coverage of the mutable region every
  frame. vision_canny writes 477x267 coordinates; the remaining right/bottom
  padding is permanently zero. Generic partial-map users retain the default
  REUSE_CAPTURE_MAP=0 behavior.

## 220 MHz acceptance boundary

A separate `efinity/sobel_220` harness instantiates the same Sobel RTL with
continuous registered input and output observation, on Ti60F225 I3.
PLL CLK0 is configured for 220 MHz using a separate 100 MHz feedback output.
The 4.545454 ns timing constraint is applied without false/multicycle exceptions
on Sobel data paths. Post-route setup slack = +1.681 ns; hold slack = +0.090 ns.
Analyzed isolated-core Fmax = 349.162 MHz (tool estimate, not measured operation).
Missing interface pins = 0; unassigned core pins = 0.

This proves the isolated four-stage core meets the 220 MHz timing target.
It does not change the integrated camera/HDMI pixel domain from 148.5 MHz,
and it does not claim an entire Canny/DDR/camera system running at 220 MHz.
The standalone timing bitstream is not programmed onto the camera board.

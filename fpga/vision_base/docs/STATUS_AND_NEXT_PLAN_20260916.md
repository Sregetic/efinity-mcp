## 下一步执行顺序与验收
### P0：当前ISP收尾（不以提升帧率代替暗部修复）
核对传感器帧长/曝光可用范围，解决软件上限1776与低照度；设计偏差大时快调、接近目标时慢调，保留读回校验。固定室内/亮窗/暗光三场景记录收敛时间、曝光/增益、噪声和色彩，避免统一加亮造成发灰。

### P1：提高真实帧率（用户本轮明确列入）
1. 将传感器/MIPI接收、有效完整帧发布、显示刷新、Canny任务完成及独立源帧结果计数分开；当前基线约29.95/60/15.25。
2. 分析Canny采集、梯度/NMS、滞后遍历、结果发布各阶段周期。现有滞后前后扫描到收敛，复杂图像耗时变化；采集60fps不等于Canny60fps。
3. 优先目标：保持480×270和完整八连通正确性的前提下，争取≥30个独立源帧结果/s；覆盖简单边缘、纹理密集及长弱边缘链，记录平均/最慢延迟与重复/丢帧。不是提前承诺所有输入均30fps。
4. 并行方向（工程方向而非启动子任务）：核对SC431HAI60fps模式、MIPI速率/时钟、DDR与缩小模块吞吐，目标真60fps采集。传感器输出与下游完整帧发布分别验证。
5. 在资源/时序允许且用户接受画质取舍后再争取Canny60fps或更高分析分辨率；不通过减少滞后遍历到错误结果、降低分析尺寸或重复旧结果伪造提升。
6. 每次RTL改动需软件参考一致、全流程P&R非负WNS/WHS、上板计数与运动场景验证。当前231 RAM10+4 DPRAM10，应先评估存储余量，不默认可复制整条Canny链。

### “理论零延迟”的修正
V1.1第7页明确不使用虚假零延迟表述，承认行缓存/流水线延迟，要求分别记录算法输出延迟和显示端到端延迟；第1、9页同时明确稳定帧/DDR任务架构。因此“彻底绕开DDR的独立直通模式”是后续低延迟优化候选，不是该技术方案明确要求的唯一结构。正式目标列为持续流式吞吐、主显示不被帧任务阻塞、实际延迟有测量；若另做绕DDR模式，单独评估与现有缓存功能共存。

### 修正后的总路线
当前ISP收尾→Canny/采集提速与延迟测量→LCD；其后推进真实ROI/帧任务/DDR统一底座，并尽早做RISC-V与最小模型的资源可行性检查→几何和局部AI、统计自适应阈值及同帧复核→应用数据/消融/最终验收。基于当前片上RAM占用，不预先保证所有模块同时驻留。

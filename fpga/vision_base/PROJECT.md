# 项目目标与实施基线

版本：V0.2，2026-09-08。目标硬件预计 2026-09-09 到位。

## 项目目标对齐

最终目标是基于 Ti60F225I3 + SC431HAI 的可配置实时视觉系统，完整覆盖赛题四基础要求和六项高阶挑战，并加入 RISC-V 控制、局部 TinyML 分析及可解释的检测结果。国一等奖是参赛目标，不以功能数量替代技术质量和验证。

软件与接口学习沿用用户已有的 Vivado 经验，主要补齐 Efinity 的 Interface Designer、SDC、IP 配置和下载流程。

目录同时包含板级Efinity工作工程与独立核心验证工程。板级工程提供相机/DDR/HDMI接入基线；独立核心提供帧所有权、ROI/stride、2PPC缩放、AXI读写、结果双缓冲发布和帧/配置编号。两层尚未全部整合，实际状态以README和results为准。原包用于复用外设驱动，不将其固定顺序读帧结构作为长期基础。

## 当前底座的关键取舍

1. **视频数据与控制分离。** 所有核心在同一 `clk` 中工作；相机、DDR、显示各自时钟域通过后续适配器连接，不直接跨域读取这些握手或 bank 元数据。
2. **帧是独立对象，不是 FIFO 的附属状态。** 采集写者取得可写 bank，只有完整成功写入才发布；显示/分析取得持有权，释放前保持帧数据有效。
3. **宽度单位唯一。** `src_width`、ROI 和输出尺寸用像素；`base_addr`、`stride_bytes` 用字节；AXI beat 为 16 字节。禁止混用“960 拍”和“1920 像素”。
4. **缩放是重采样。** 首版最近邻精确实现 floor 映射；不是改输出时序或丢掉边缘像素。双线性和缩小抗混叠后续单独实现、比较资源与画质。
5. **输出流允许暂停。** 缩放器是帧任务渲染核心，行读取会有气泡；不直接等价于 HDMI 连续有效区供数器。上板需结果帧缓存或经过预算的异步显示缓冲。
6. **实现即验证，不把占位模块算完成。** 摄像头写 DMA、AXI 仲裁、显示扫描、算法、RISC-V/AI 尚未接入时，状态保持待实现。

```text
SC431HAI -> CSI/解包 -> 去 Bayer/格式处理 -> 采集写入器 -> 源帧 DDR
                                                   frame_pool 管所有权
                                                            |
                              +-----------------------------+------------------+
                              |                                                |
                    ROI/AXI行读 + 最近邻缩放                         analysis帧任务
                              |                                      Canny/几何/AI
                       结果帧写入/显示缓冲                                      |
                              +-------------------------- 同帧结果 ------------+
                                                         |
                                                   合成 -> HDMI / DSI
```

图中采集格式适配、DDR 多主仲裁、显示扫描/合成、算法和 SoC 为后续工程；RGB565结果写入器与帧任务调度/发布已接成可仿真闭环。当前核心的端口是这些模块的确定连接边界，而非宣称已完成整条链。

## 内存与带宽预算（示例，待上板）

- 1920×1080 RGB565 有效数据为 4,147,200 B/帧；四个源帧 bank 约 15.82 MiB。按 4 MiB 对齐步长规划时四帧占 16 MiB。
- 两个同尺寸结果帧约再占 8 MiB（按 4 MiB 对齐）；算法中间图和 AI arena 独立分配，确认真实 DDR 容量后填写地址表。
- 1080p60 RGB565 一写一读约 497.664 MB/s。若渲染器额外读源帧、写结果，另加带宽；行缓存复用减少局部放大的重复源读取。
- 当前 128-bit AXI reader 为单在途 burst、32-bit/2PPC 像素回传，双行缓存预取与结果写入并行。仿真证明功能，具体吞吐由控制气泡、频率、仲裁、内存和目标缩放比例决定；必须测量而非以总线宽度估计达标。
- 控制与 AI 先单核 RISC-V、小型模型，依实际算子裁剪硬件。Lite/Standard 是互斥综合配置，不做成改变资源占用的运行时菜单。

## 分阶段接受条件

### P0：今天，主机功能基线

交付可运行的 RTL、接口说明和单入口验证：ROI 放大/缩小、padding stride、跨 AXI burst/4 KiB、背压稳定、帧中参数不变、帧持有不被覆写及同时事件处理。长案例包含 1280×720 到 1920×1080，日志分别报告周期和像素数；不折算为未经综合确认的硬件 FPS。

### P1：硬件到位后的第一轮

核对 PCB/相机/转接板，冻结引脚和时钟；恢复正确的 vendor HDMI 直通工作点；确认 DDR 校准、稳定采集和显示。完成后将本底座接到真实 DDR，先做固定测试图 ROI，再接摄像头。目标是同一块硬件上证明“直通 + 真缩放 + 冻结”。

### P2：赛题完整性

逐项完成 B1-B5、A1-A6。基础视频和可控取图稳定后才增加复杂算子。每项保留正确性、资源、时序和实际运行证据；不要为了界面效果跳过完整 Canny 连接。

### P3：软硬件协同和应用

接入最小 RISC-V 与静态 INT8 模型，尽早测资源和 arena；再接动态 ROI、实际样本和自适应调度。基础/高阶功能仍保留。AI 与传统算法各自贡献通过相同测试集比较。

## 本轮不做的工作

不改原压缩包、不直接覆盖供应商示例、不写未经实物核实的引脚、不声称已上板；不加入 Linux、多核、大模型、云端或无关展示功能；不自动更新所有 IP。没有完整板卡 top 和约束前，不提供名义上的“已完成 Efinity 工程”。

## 建议用户确认的方向

按已对齐方向推进：固定1080p60主链；HDMI优先、LCD随后；全部基础/高阶保留；RISC-V与AI实际集成；底座适配多个视觉方向、暂不选定主应用。新算法是否达到每帧实时需单独验收。

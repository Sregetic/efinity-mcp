# KEY1返回键：最新菜单、实时目标列表与完整固件已固化Flash

## 当前按键与固化内容

KEY1=P14现在经过同步/消抖，短按负责打开菜单、返回、取消编辑和关闭菜单，取代原长按KEY0。KEY0短按保持原功能：菜单内进入/确认，菜单外快速切换显示；长按KEY0不再产生返回或确认事件。KEY2/3短按上下、原长按冻结/历史保留。CONFIG控制器未改，仍作为重新配置/恢复入口。

KEY1原来驱动的4路PLL复位和CSI接收器3个复位输入统一从KEY1分离，保持未复位电平；系统自身的PLL失锁复位链保持。原i_arstn端口/引脚不更名，现只用于KEY1输入与诊断，不再用作功能复位源。

最新实时全景、动态0–4目标列表、逐行来源/选择关联、普通几何与人脸独立刷新均保留。Canny检测/连续显示、几何/字母/人脸数值判定和独立AI算法没有修改。

- **配置Flash地址0**：1060920B配置，包含125字中文点阵、K1提示、四键输入、最新目标列表高亮和原整机硬件。厂商hostx1完整读回校验通过，SPI低功耗模式off。
- **应用Flash地址0x700000**：381216B VBO1包，即32B CRC头＋376784B完整应用＋4400B原权重。实际逐字节读回一致。
- **自启动**：重新配置后，ROM从Flash自主加载，BOOT7、JEDEC EF6017、CPU1、控制ABI0x26103005、M7 ABI0x26103072、AI启动自检2。376784B应用和4400B权重的全部DDR实际字节匹配；该次启动后没有USER1应用下载。

菜单不是单独临时加载的程序。当前配置、完整应用与权重已经成套固化；CONFIG或断电后会回到本版，而不是此前冻结列表版本。完整配套在`release/`，组合回执为`release/flash_receipt.json`。

## 已处理的执行问题

烧录前的功能和实时窗口均完成，但恢复检查错误地要求关闭ROI时的历史硬件坐标跨FPGA重配后完全相同。前值ROI关闭、寄存器保留旧裁剪[1012,644,908,436]；新硬件关闭时报告默认全幅。现有control_service_step在禁用时不写几何寄存器，实际图像和逻辑请求均为关闭ROI。测试据此只比较有效配置及菜单；启用ROI时仍严格比较坐标/尺寸/位置，未修改生产读回语义。已复用完成窗口，保留原失败和修正依据。

该比较失败后的包装命令漏检查Python退出码，提前启动了Flash备份流程；发现时检查实际阶段仍在有界备份，没有观察到擦写。核对既有禁用ROI契约、修正验收后继续；原生Flash脚本自身仍先完成8MiB备份和布局/CRC检查才允许擦写。后续配置写入明确检查返回状态与独立验证回执。未把缺少回执当作成功。

配置首次校验未通过，厂商工具内置max-clk等待重写后，最终完整hostx1校验成功。失败轮次与成功记录保留在`flash/config/write.log`；没有修改厂商代码或USB设置。

# RAW 颜色诊断 2026-09-16

构建26091608增加只读稀疏RAW探针（80×45个2×2 Bayer块），不改变曝光1776半行、Gamma、增益、视场、Canny或DDR参数。新增可在场消隐切换的RGB通道排列；初始保持旧排列1，随后通过JTAG命令6切到排列0（标准RGB），取消输出G/B交换。

## 实测
- 3600个RAW块，共14400个样本；最大值分别105/169/164/159，未采到 >=250 的点。
- 两个对角候选的绝对差中位数分别30（p00/p11）和1（p01/p10）；支持绿色位于p01/p10，即RGGB或BGGR。
- 这次快照仅代表采样时的当前场景；不据此否定此前其他构图存在过曝。
- 当前debayer按RGGB合成输入，扣除RAW黑电平16后，260个内部像素对全部得到预期的独立R/G/B数值。
- 因此先取消额外的B/G交换，再用明确红色物体判定剩余R/B方向；后续白平衡另用未饱和中性目标进行。
- 最新P&R：WNS +0.356ns，WHS +0.024ns，JTAG SRAM下载完成。RAW取样模块单测覆盖字节顺序、双时钟读出、快照保持、重复触发。

## 红色目标确认与修正
用户放置红色目标，并确认标准RGB排列0下红色显示为蓝色。中央120块RAW均值：p00=77.775，p01=111.2，p10=111.0333，p11=159.3；最大170，无接近饱和样本。红色目标在p11响应最高，结合两个绿样本位于p01/p10，确定当前帧缓冲输出的Bayer排列应按BGGR解释（不等同于推断传感器未镜像前的原生排列）。

现有去马赛克针对RGGB的合成输入测试通过；因此当前物理R/B与内部命名相反。旧输出排列1又额外交换G/B，形成错误的物理颜色映射。先去掉G/B交换后红物变蓝，最终使用排列2：R取gamma_bdata，G取gamma_gdata，B取gamma_rdata。

JTAG已即时设置排列2，RAW探针读回color_order=2确认生效。曝光1776半行、Gamma和所有数值增益未变。红/绿/蓝三个BGGR合成目标分别检查260个内部像素对，全部通过，使用实际增益256/230/256和黑电平16。

26091609把排列2设为默认，编译和下载结果另存build09子目录。现有内部通道变量仍沿用旧命名，后续白平衡应按修正后的物理R/G/B解释，而不是仅按gamma_rdata/gamma_bdata名称调参。

目前只确认通道映射；亮度与白平衡最终效果仍待用户观察。本轮不再降低曝光或改变Gamma。

红蓝交换生效后，用户仍反馈红物接近白色、深蓝色很淡，因此没有将交换通道宣称为完整修复。增加中央256×256区域的Gamma前/后和最终输出统计，并增加Gamma旁路用于后续受控对照，默认Gamma保持开启。

用户确认放置白纸后，0a测得Gamma前内部R/G/B中位数33.5099/47.7437/52.9134；映射到物理颜色为52.9134/47.7437/33.5099。后级输出117.035/112.288/95.984。ROI近饱和计数均为0。

按最弱通道归一化，原内部增益256/230/256调整为256/161/162，对应物理R/G/B增益162/161/256（Q8.8）。曝光1776半行及Gamma曲线不变。新固件默认颜色排列2、默认使用新增益，物理通道增益还可用命令8/9/10在场消隐时更新并由诊断页8读回。

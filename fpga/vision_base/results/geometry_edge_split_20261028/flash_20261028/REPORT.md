# M7统一边缘几何与独立刷新：Flash固化完成（2026-10-28）

## 配置、应用、菜单均已固化

配置1073799B写入Flash 0地址，应用/权重210912B VBO1包写入0x700000。配置厂商hostx1完整校验及应用逐字节读回通过。ROM从Flash自主加载206480B应用和原4400B权重，全部实际DDR字节一致；该验证只halt/read/resume，没有USER1程序下载。启动状态BOOT7、JEDEC EF6017、CPU1，AI启动自检2（通过）。

用户按提示CONFIG或断电重载后确认“菜单出现，画面正常”。重载方式未具体区分；这项记录为用户现场确认。本机随后未枚举到FTDI，故未取得该次重载后的自动版本回读。写后完整Flash校验与先前ROM自加载字节证据保留，不冒充此次物理重载的自动读回。

## 上板发现的问题与修复

连接初始诊断接口不匹配本次完整工程；当前Flash配置与选定位流的实际字节也不一致。因此先恢复已验证的配套SRAM位流做检查，固化时一并更新配置区。Canny检测/追踪/连续重建及显示源码没有改，使用的仍是已验证的同一位流。

新固件首次上板暴露M7调度错误：消隐期roi_frame_ok低，使新快照暂时不合格；原cancel把上一轮已完成结果和独立人脸任务一起清掉。日志preflight_lanes.log显示GEO3发布序号与两路有效序号反复清零。用相同场景补充RV32I测试，旧代码在service line76复现失败。

修复集中在geometry_m7_service.c：新快照失效只释放该快照，不清理已复制的独立任务/已完成结果；共享位图仅在COPY阶段依赖快照有效位；读到新token后重新读取其有效位。模式、阈值、视图/上下文变化仍取消旧结果。补充消隐失败、共享复制失效和token晚于状态读取的测试通过，冻结换源等原服务测试继续通过。分类器和Canny没有改，26组识别/显示证据复用。

GEO3诊断[22]表示配置等导致的整任务取消，[23]表示本次新快照被拒绝；后者可在消隐期增长，不表示视频坏帧。修复后本轮8秒采样期间已完成结果保持有效，两路序号正常前进。

## 固化后的实际运行结果

- 自由运行8.025秒，两路各完成43次，约**5.36次/秒**。
- 最近一次输入快照到几何完成**179.47ms**，到人脸路完成**180.20ms**。
- 当前画面未检出目标；这些是当前场景的处理更新统计，不能外推为复杂人脸/多目标速度或准确率。
- 视频约**29.97fps**；RAW溢出、采集丢弃、扫描坏帧均0。
- Flash加载的完整应用通过长KEY0菜单、二级导航、中值KEY0立即切换及恢复。自动检查结束时为M7/MED1/F0、一级菜单，无源持有/冻结；用户随后重载并确认菜单/画面正常。

计数窗口中CPU自由运行，仅在前后各暂停读取一次；临时使用1MHz执行边界控制与计时寄存器读取，状态数组仍用已验证5kHz。第一次5kHz全程控制测量额外包含约2秒调试时间，未用作更新率结果，原日志保留。

## 资源与当前交付

硬件58458XLR/243RAM/64DSP不变；原WNS+0.109ns/WHS+0.026ns继续对应同一位流，没有重做未改动的P&R。最终应用206480B、BSS201748B；相对原447344B/312100B应用，分别减少240864B/110352B。程序仍含完整菜单、FOMO/连接组/原基础AI；M7只用统一边缘轮廓几何，Pico模型不再链接。

本机完整交付在../release/，本轮构建在firmware/，实际固化包在app/vision_boot.bin。此前../firmware_final/是206592B的离线候选，已由本次含快照时序修复的206480B版本取代，不再用于烧录。

当前板原始8MiB Flash备份为app/flash_before.bin。应用烧录使用现有scripts/program_vision_boot_flash.ps1，校验路线改为这块板已验证的hostx1，地址/时钟/授权门禁保持。配置烧录使用program_config.ps1；厂商检测首次校验不一致后，按内置最大页等待重写，最终完整校验通过。未修改厂商代码。

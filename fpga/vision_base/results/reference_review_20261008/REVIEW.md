仅抽取相关源码和包内历史报告供审查，当前项目 RTL、固件、位流与板上参数保持。本轮没有执行压缩包中的脚本或进行硬件烧录。

## 结论

参考主链是 **OV5640 RGB565 → 灰度 → 全1280×720四方向Sobel → 8位灰度强度显示**。
它不是 Canny，也没有在 FPGA 主链接入中值/高斯/非极大值抑制/滞后连接/形态学去噪。
整洁观感的主要代码差异是原分辨率处理和连续灰度强度显示；相机内部的成像处理也不同。
灰度显示让弱梯度较暗，并不等于删除了这些噪声。

实际显示的数学形式：

```text
Y = floor((306R + 601G + 117B) / 1024)
Gmax = max(abs(G0), abs(G45), abs(G90), abs(G135))
display = 255 if Gmax > 510 else floor(Gmax / 2)
```

例如梯度20显示为10，梯度200显示为100；不是只要成为候选边缘就显示255。
这种强度过渡改善视觉柔顺程度，但没有专门的亚像素定位或抗锯齿重建。
没有NMS意味着它也不保证所有边缘都是单像素宽。

`Sobeledge_proc.v:155` 的注释声称输入经过中值，但顶层直接连接灰度输出，工程设计文件清单也没有这条中值处理路径。
可选 `bin_en=1` 使用的是 `Gmax >= matrix_p22_dly`，即中心灰度作阈值，并非当前显示分支；不应据此解释它的实际观感。

## 相机端的处理

说明文件指明 AN5640 模组。实际 OV5640 初始化表包括：

- `I2C_OV5640_1280720_Config.v:96-99`：RGB输出，以及注释标明的lens correction/raw gamma/坏点/CIP开关。
- `:202-218`：Gamma曲线表。
- `:240-252`：CIP锐化和DNS降噪阈值/偏移参数。
- `:299`：SDE/CMX/AWB开关。

因此参考输入不是我们 SC431HAI 的 RAW10 数据。OV5640内部噪声处理、重采样等功能可能贡献了实物观感；相机端效果与Sobel算子效果应分别评估。
官方说明支持其具备降噪、Gamma、锐化和720p binning后重采样功能；它并不证明本参考工程的全部功能都已在实物中开启或验收：
https://www.ovt.com/press-releases/omnivision-launches-optimized-quarter-inch-5-megapixel/

## 当前实现的对应差异

- 当前 `vision_canny.sv:17-29` 先做4×4区域平均，分析尺寸480×270；显示1920×1080。它的细线显示不是1080p检测，节点位置仍落在4显示像素网格。
- 当前 `vision_display.sv:33,36-37` 的Sobel/Canny是硬二值或固定红色显示。当前Sobel本身是全1920×1080处理，480×270降采样问题仅属于Canny分支。
- 当前 `vision_sobel.sv:28-32` 的梯度幅度是 `abs(Gx)+abs(Gy)`，参考使用四方向最大响应。两者幅度尺度不同，阈值数值不宜直接照搬。
- 当前灰度系数77/150/29除256与参考306/601/117除1024接近，这不是主要观感差异。
- 当前 Canny 有高斯、NMS、完整滞后连接和小组件剪除，算法链比参考更完整。
- 当前 Canny 的中值是脉冲保护式：`vision_canny_denoise.sv:27-31` 仅替换不受邻域支持且差值大于64的异常点。它不是对每个像素无条件平滑，开启中值不等于普通细小扰动都会被平滑。

## 缓存与借鉴范围

参考行缓存 `extract_region_c_shiftram_xtap.v:19-39` 是整条移位链。包内2024.2历史综合报告 `Ti60_Demo.res.csv:121` 显示该层使用2624 SRL、72 LUT、0 RAM。
这是用逻辑移位资源保存行数据，不是无成本缓存，也不是在我们2026.1/I3整机上的新增资源实测。
另外矩阵模块的DISTANCE硬编码1280，扩展1080p还需同步修正抽头间距。

适合借鉴的是：全分辨率流式定位、边缘强度显示、输入端降噪与亮度稳定处理。
简单增加强度显示可复用现有全分辨率Sobel梯度，不需要再存一张整帧；具体新增逻辑仍应以实际构建为准。
完整Canny及其帧绑定应保留；Sobel强度显示改善与Canny检测分辨率/实时跳动修复应分开验收。

# 验收说明

## 验证层级

| 层级 | 验证内容 | 能证明什么 |
|---|---|---|
| 单元/软件集成测试 | 路径限制、配置、任务、替身子进程、报告、审批门控 | 适配器软件行为 |
| MCP 协议测试 | 真实 SDK 启动、stdio 握手、工具发现、正常调用和错误响应 | 客户端可按协议调用服务 |
| Efinity 实机测试 | 真实安装、许可证、官方示例 map/compile、真实日志和产物 | 该版本的 EDA 接口兼容性 |
| FPGA 板卡测试 | 下载器枚举、JTAG、引脚/电压审查、实物功能 | 对应硬件配置可用性 |

**软件测试不能替代后两层。** `tests/conftest.py` 产生的位流和报告都写有 SYNTHETIC，不可下载到任何 FPGA。

## 首轮 Windows 验收顺序

1. 在 Efinity GUI 中打开 VF-Ti60F225 厂商示例，记录 IDE/补丁版本、器件完整型号、板卡版本。先手动证明原工程可构建；保留原件。
2. 用独立 Python 虚拟环境安装本服务，将审核后的工程复制到 ASCII 路径并登记 TOML。保持 `trusted=false` 与 `allow_programming=false`，运行 `--doctor`；也可先用 `--init-config` 生成不授权执行的新配置。
3. 运行 `--check-mcp` 测试真实协议连接，再用 `--print-codex-config` 输出客户端配置段。通过 MCP 检查工具列表、`get_project` 和 `preview_build`。人工核对实际 Efinity Python、脚本路径和输出目录。
4. 审核全部 Tcl、脚本、外部引用和 I/O 约束后，在本地设置该项目 `trusted=true`，重启服务。先跑 `map`，核对退出码与日志；再跑 `compile`。
5. 将 GUI 与 MCP 两次结果的器件、资源、时序约束、关键路径及位流产物逐项核对。出现未约束路径不能因为 WNS 非负就宣称时序合格。
6. 将真实报告的脱敏小样本作为后续解析器 fixture，注明安装版本、原始行号及允许再分发的范围。不得上传许可证、私有 IP 或受限源文件。
7. USB 枚举后先由人确认目标序列号。只有独立验收通过、引脚电压安全、操作人明确同意时，才开启 JTAG。先 `preview_program`，核对文件 SHA-256，再调用 `program_device`。

## 必须记录的真机证据

记录版本、工程 Git 提交、XML 哈希、命令、退出码、运行时间、原始日志、报告、目标板及下载器序列号。图像链路的帧率、时延、图像正确性需要额外试验，不由 MCP 或编译成功自动得出。

当前仓库不包含任何真实 Efinity 构建或板卡烧录的验收结论。CI 状态与本地测试结果以运行记录为准，不能用绿色 CI 标识代替 FPGA 功能验证。

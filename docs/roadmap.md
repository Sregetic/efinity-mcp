# 范围与后续里程碑

## v0.1：先形成可测试的适配层

已有工程注册、只读检查、受控构建、异步任务、日志/报告读取、产物追踪、受控 JTAG、测试与 stdio 客户端配置。项目源码仍由原来的编辑器/代码代理修改，本服务不提供通用文件写接口。

## 下一关：本机 Efinity 2026.1 验证

优先验证 Windows 安装目录和厂商 Python 位置，使用老师已有的 VF-Ti60F225 示例完成 map/compile。保存真实报告后，再开发有版本标记的 timing/utilization 解析器；缺字段返回 unknown，不补零、不推断成功。需要检查不同时钟、setup/hold、未约束路径，而不是只看一个 WNS 数值。

## 后续按比赛需要扩展

按实际需求追加经核验的工程模板导入、源文件登记、受控参数修改，以及 Efinity Python API 适配。RISC-V、相机、Canny、板卡配置都是 FPGA 工程本身的任务，不通过增加 MCP 工具名称就自动获得。

HTTP/OAuth、远程 Hardware Server、Flash 更新、JTAG 调试器控制、无人值守自动修改 RTL 暂不实现。不得为适配器扩张范围而挤占赛题四图像链路的开发时间。

## 已知限制

构建只对已信任工程开放，不是恶意项目沙箱。输出目录会被 Efinity 写入，不保证完整源文件快照；不要在构建中途修改工程。异常崩溃可能留下进程和锁，必须检查进程后人工清理。任务和位流快照保留在 `.efinity-mcp`，需要定期人工清理；不做未经授权的自动删除。日志限额通过轮询监测，短时间可能超过阈值，不是硬磁盘配额。单一工作区任务串行；多个工作区/GUI 的并发不由它协调。
